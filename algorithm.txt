Теперь давай реализуем следующий алгорит:

1. По ссылке, переданной в качестве параметра, качается html-страница в каталог Pages.
2. Из этой страницы выделяется ссылка (href) на квартиру по следующим параметрам: 
	1. **Основной и самый надёжный способ** — взять `href` у тега `<a>` с атрибутом `data-marker="item-title"`. Этот элемент присутствует в каждом объявлении, содержит полный 		URL и наиболее устойчив к изменениям вёрстки.
	2. **Запасной вариант** — если заголовок по какой-то причине отсутствует, используйте атрибут `data-item-id` у контейнера `div[data-marker="item"]`. Идентификатор 	объявления можно подставить в стандартный шаблон ссылки, например: `https://www.avito.ru/.../{data-item-id}`.
3. Переходим по ссылке, полученной в шаге 2.
4. Используя библиотеки requests и BeautifulSoup парсим значения страницы:

	Страница имеет следующую структуру (селекторы и поля):

	1. Заголовок: h1[data-marker="item-view/title-info"] → текст.
	2. Полная цена: span[id="bx_item-price-value"] или span[data-marker="item-view/item-price"] → числовое значение (удалить пробелы и символы).
	3. Цена за м²: p.d870ed3c55f3c0c1 (внутри блока цены) → текст, извлечь число.
	4. Адрес: span._8360df6eedcf8d52 внутри div[itemProp="address"] → полный адрес.
	5. Метро: все span._22d8cf68e753a9b9 внутри блока адреса. Каждый содержит название станции, цвет линии и время пешком. Извлеки список словарей: {name, line_color, walking_time} (время можно извлечь из вложенного span._975960bc91729d0a).
	6. Описание: div[data-marker="item-view/item-description"] → текст (все параграфы внутри).
	7. ID объявления: span[data-marker="item-view/item-id"] → текст.
	8. Дата публикации: span[data-marker="item-view/item-date"] → текст.
	9. Общее количество просмотров: span[data-marker="item-view/total-views"] → число.
	10. Просмотров за сегодня: span[data-marker="item-view/today-views"] → число в скобках (можно извлечь регуляркой).
	11. Имя продавца: span._871bd196e38e7a53 внутри блока data-marker="seller-info" → текст.
	12. Статус продавца: div[data-marker="seller-info/label"] → текст.

	13. Характеристики квартиры: находятся в первом блоке div[id="bx_item-params"] с заголовком "О квартире". Внутри ul с классом a428a905bbb93d32, каждый пункт li содержит span.d6e8fd2e3d52b32a с названием параметра и следующий текстовый узел (или дочерний элемент) со значением. Названия: "Количество комнат", "Общая площадь", "Площадь кухни", "Жилая площадь", "Этаж", "Балкон или лоджия", "Тип комнат", "Высота потолков", "Санузел", "Окна", "Ремонт", "Стоимость ремонта", "Способ продажи", "Условия продажи". Извлеки словарь, где ключи — это названия (или их нормализованные версии).

	14. Характеристики дома: второй блок div[id="bx_item-params"] с заголовком "О доме". Аналогичная структура. Названия: "Тип дома", "Этажей в доме", "Пассажирский лифт", "В доме", "Двор", "Парковка". Также извлеки словарь.

	15. Данные из блока "Проверка в Росреестре": блок div[data-marker="domoteka-entry-block"]. Каждый пункт — p[data-marker="TeaserData.item"]. Текст содержит информацию: "1 собственник", "Последняя смена собственника ...", "Не найдены ограничения ...", "Совпадают площадь, адрес и этаж". Можно извлечь как список строк или отдельные поля (например, количество собственников, дата смены, обременения, совпадение). Для простоты извлеки весь текст каждого p и сохрани в список.

	Все поля могут отсутствовать — используй try/except или проверку на None, чтобы не падать.
5. Записываем значения в CSV файл с разделителем "\t". Названия столбцов должны быть на русском. Плюс, если в полученных в п.4 значениях есть табуляция, необходимо ее удалять или заменять пробелом.
6. Удаляем страницу по конкретному объявлению.
7. С задержкой 3-6 секунд переходим к п.2 в нем к следующему объявлению и далее п.3, п.4 и т.д.

7.1. Когда все страницы на стартовой странице (полученной в п.1) пройдены, необходимо проанализировать HTML-код веб-страницы с объявлениями и 
найти URL для перехода на следующую страницу (пагинация). Используй приведённые ниже правила и приоритеты, 
чтобы выбрать наиболее надёжный вариант.

8. Определи блок пагинации
- Найди контейнер, содержащий элементы навигации по страницам. Обычно это элемент с классом, содержащим `pagination`, `pager`, `pages`, или атрибутом `data-marker="pagination"`, `role="navigation"`, `aria-label="Пагинация"`.
- Если таких блоков несколько (например, сверху и снизу), отдай предпочтение нижнему блоку (он чаще содержит полный набор ссылок).

9. Ищи прямую ссылку «Следующая страница»
- Сначала проверь наличие элемента с текстом/подписью, явно указывающим на следующую страницу. Ищи:
  - Кнопку или ссылку с текстом «Вперёд», «Далее», «Next», «Следующая», «→» и т.п.
  - Атрибут `rel="next"` (наиболее надёжный признак).
  - Атрибут `data-marker="pagination-button/nextPage"` (как в примере).
  - Класс, содержащий `next`, `forward`, `arrow-right`.
- Если такой элемент найден, возьми его атрибут `href`. Проверь, что он не пустой и не равен `#`. Используй его как результат.

10. Если прямой ссылки на «Далее» нет, найди ссылку на последнюю страницу
- Поищи ссылку с текстом/значением, соответствующим последней странице (например, «Последняя», «Last», или число, совпадающее с общим количеством страниц).
- Если известен номер текущей страницы (его можно извлечь из активного элемента пагинации или из URL параметра `p`), и номер текущей страницы меньше номера последней, то сконструируй URL следующей страницы, увеличив параметр `p` на 1 (или аналогичный параметр вроде `page`, `offset`).

11. Если нет ни того, ни другого, используй ссылку на следующую числовую страницу
- Найди все ссылки на страницы (элементы `<a>`, содержащие только число в тексте, и имеющие атрибут `data-marker="pagination-button/page(...)"` или похожий).
- Определи текущую активную страницу (элемент с классом `current`, `active` или `aria-current="page"`).
- Затем найди среди остальных ссылок ту, у которой число на единицу больше текущего номера.
- Возьми её `href`.

12. Обработка частных случаев
- Если ссылка содержит относительный путь (начинается с `/`), дополни его протоколом и доменом (например, используй текущий `window.location.origin`).
- Если ссылка является якорем (`#`) или вызывает JavaScript (`javascript:void(0)`), пропусти её и перейди к следующему кандидату.
- Если ссылка ведёт на ту же страницу (отсутствие изменений в параметрах пагинации), не используй её.

13. Проверка на последнюю страницу
- Если найденная ссылка указывает на текущую страницу (например, параметр `p` не изменился), или все перечисленные методы не дали результата, значит, следующей страницы нет. Верни `null` или пустую строку.

14. Загрузка следующей страницы
- Когда URL для следующей страницы найден (без лишнего текста), необходимо загрузить html этой страницы и перейти к п.2 данного алгоритма.

Пример применения
Для приведённого фрагмента:
```html
<a class="styles-module-item-zINQ7 styles-module-item_link-GS05K" aria-label="Страница 2" data-value="2" data-marker="pagination-button/page(2)" href="/moskva_i_mo/kvartiry/prodam-ASgBAgICAUSSA8YQ?context=H4sIAAAAAAAA_wEmANn_YToxOntzOjE6InkiO3M6MTY6InJhVHhPbm1PbHpjbGg4WEYiO32ZR0mWJgAAAA&amp;p=2"><span class="styles-module-text-Z0vDE">2</span></a>
```
Агент должен определить, что это ссылка на страницу 2. Если текущая страница – 1, то эта ссылка и есть следующая. URL будет: `/moskva_i_mo/kvartiry/prodam-ASgBAgICAUSSA8YQ?context=...&p=2` – его и следует вернуть.

Если же текущая страница – 2, агент должен найти ссылку на страницу 3 или кнопку «Далее», используя описанные выше шаги.
